# Local settings

How `gl` learns the instance URL, the token, and (optionally) the project. Never `Read` these files or run `token_cmd` yourself — `gl` does both so the token never enters the transcript.

## Files and precedence

Two Markdown-with-frontmatter files; only three keys exist:

| Key | Where | Meaning |
|---|---|---|
| `url` | user file; project may override | Instance base URL, e.g. `https://gitlab.example.com` (relative-URL installs: `https://host/gitlab`) |
| `token_cmd` | user file; project may override | Shell command whose stdout is the PAT — recorded verbatim |
| `project` | project file only | `group/subgroup/name` — pins the project when the git remote doesn't map |

- **User:** `~/.claude/gitlab-client.local.md` — written by `/gitlab-client:setup`; required.
- **Project:** `<repo>/.claude/gitlab-client.local.md` — optional, gitignored.

Precedence, highest first: CLI flags (`--url`, `--project`) → environment (`GITLAB_CLIENT_URL`, `GITLAB_CLIENT_TOKEN`; when the token env var is set, `token_cmd` is not run) → project file → user file. Unknown keys warn on stderr and are ignored. Edits apply on the next `gl` call — nothing to restart.

## Minimum user file

```markdown
---
# Generated by /gitlab-client:setup. Edits take effect on the next gl call.
url: https://gitlab.example.com
token_cmd: ksm secret notation keeper://abc123/field/password
---
```

## `token_cmd`

The command line is recorded verbatim and run through the shell — pipes, env vars, `$(…)` all work. One line each:

- Keeper: `ksm secret notation keeper://<uid>/field/password`
- pass: `pass show work/gitlab-pat`
- 1Password: `op read "op://Work/GitLab PAT/credential"`
- env var: `printf '%s' "$GITLAB_TOKEN"`

Multi-line commands use the block scalar: `token_cmd: |` with the script indented below.

Rules: the command must exit 0 and print exactly one non-empty stdout line. On failure `gl` exits 2 showing the exit code and stderr — never stdout, so the token can't leak through an error message.

**Never put a literal token in the file** (`token_cmd: echo glpat-…`): `/gitlab-client:setup` and `/gitlab-client:doctor` may display the `token_cmd` line, and a literal token would land in the transcript. Export it and use the `printf '%s' "$GITLAB_TOKEN"` form instead.

## Project file

Add `<repo>/.claude/gitlab-client.local.md` only when project resolution needs help: `origin` isn't the GitLab remote, the instance is a relative-URL install, or the repo maps to a different project path than its remote suggests.

```markdown
---
project: platform/backend/api
---
```

Must be gitignored — `/gitlab-client:setup` adds `.claude/*.local.md` to `.gitignore` when it writes one.

## Token scopes

- `read_api` — everything read-only, including job logs and artifacts.
- `api` — required for any write (MRs, comments, retry/cancel/play/trigger).
- `read_repository` alone is **not** enough: it covers git-over-HTTP, not the REST API.

`/gitlab-client:doctor` shows the token's scopes and expiry (via `GET /personal_access_tokens/self`) and warns when expiry is near. Tokens created without an expiry get one forced at GitLab 16.0 — expect previously immortal tokens to start expiring after an upgrade.
