# gitlab-client on bare AL2023, and for Codex — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `gl` and its setup/doctor run on bare Amazon Linux 2023 (`python3` 3.9, no git, no uv), gitlab-client is no longer deprecated, and it ships for Codex as well as Claude Code.

**Architecture:** The code already runs on 3.9; the work lowers the declared floor and pins the dev venv to 3.9 so `make check` (and CI) test on it, adds one missing-git message, then ports the plugin to the repo's dual-client layout (shared skills under `skills/`, thin Claude wrappers in `commands/` and `agents/`, a portable `plugin.json`, a Codex catalog entry).

**Tech Stack:** Python 3.9 stdlib (`gl`), uv + pytest 8.4 + ruff + ty (dev only), Markdown skills, JSON manifests.

**Spec:** `docs/superpowers/specs/2026-11-15-gl-al2023-design.md`

## Global Constraints

- Only `plugins/gitlab-client/`, the two catalogs, repo-root docs (`CLAUDE.md`, `AGENTS.md`, `README.md`) and `scripts/tests/test_portability.py` change. mysql-client, openvpn-on-demand and pytest-httpchain are untouched.
- `gl` runtime: Python ≥ 3.9 standard library only, no venv, no new dependency. No 3.10+ syntax or stdlib.
- The shared `Makefile` is not changed.
- Version **0.2.0** everywhere (both manifests, both catalog entries, `pyproject.toml`, `uv.lock`, `__init__.py::__version__`).
- One description, byte-identical in all four places: `Drive a self-managed GitLab 15.x — browse repos, read and open merge requests, debug CI pipelines and job logs — through a bundled REST client with an allow-listed write policy.`
- Shared files (`skills/**`, `setup-checklist.md`) carry no `${CLAUDE_PLUGIN_ROOT}`, `AskUserQuestion`, `` `Read` `` tool name, or "Claude" as the actor; paths are `<plugin-root>`, resolved from the skill's own directory. Claude-specific names stay in `commands/`, `agents/`, and an explicit "In Claude Code, …" line.
- Setup/doctor are named `gitlab-client-setup` / `gitlab-client-doctor` in shared text and in `gl`'s messages; `/gitlab-client:setup` / `:doctor` are the Claude Code aliases.
- Settings files stay `~/.claude/gitlab-client.local.md` and `.claude/gitlab-client.local.md` for both clients.
- New Python/shell files start with `# SPDX-License-Identifier: AGPL-3.0-only`. Commits end with the session's attribution lines.

## Review Focus

1. **No git, run from a subdirectory of a clone:** with no repo root to find, `gl` reads `.claude/gitlab-client.local.md` from the current directory only — it must work from the project root, and doctor's WARN must say so. Pinned by `test_project_file_is_read_from_cwd_without_git` (Task 2).
2. **The suite on a machine without git** (the AL2023 container): tests expecting "gave nothing" must not flip to the new git-missing message. Pinned by passing an explicit `which` in those tests (Task 2) and by the container run (Task 7).
3. **Codex sandbox without network:** a `gl` call fails with a connection error; the assistant must ask for network approval, not report GitLab as down. Pinned by the client-compatibility section and its grep (Task 4).
4. **A Claude Code user told "run gitlab-client-setup":** that name has to resolve there too, as the plugin skill `gitlab-client:gitlab-client-setup`, with `/gitlab-client:setup` named beside it. Pinned by `claude plugin validate` and the frontmatter grep (Task 3).
5. **CI builds the venv on 3.9:** `uv sync --locked` must honour `.python-version`, and the launcher test's `python3` must be the 3.9 one. Pinned by running CI's exact command and checking `uv run python3 --version` (Task 1).
