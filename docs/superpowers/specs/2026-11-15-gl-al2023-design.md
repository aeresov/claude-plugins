# gitlab-client on bare Amazon Linux 2023 — design

## Intent

`gl` (gitlab-client's bundled REST client) must run on a bare Amazon Linux 2023 host: `python3` 3.9 (3.9.25 in the
current image), no uv, no git. The other plugins (mysql-client, openvpn-on-demand, pytest-httpchain) run in projects
where uv and a newer Python are expected; they keep their current floors and are not touched. gitlab-client is
maintained again: the "deprecated" notices go.

## Findings that shape it

- The code already runs on 3.9: the full suite passes inside the official `amazonlinux:2023` image (144 passed, 1
  opt-in live test skipped), and `ty --python-version 3.9` / `ruff --target-version py39` are clean.
- What blocks AL2023 is the gate: checklist check 1 requires `python3` ≥ 3.10, so `/gitlab-client:setup` stops and
  `/gitlab-client:doctor` fails. pyproject, README, SKILL.md and CLAUDE.md also claim ≥ 3.10.
- git is not on bare AL2023. `gl` copes (`--project`, or `project:` in the project settings file), but its message
  ("`git remote get-url origin` gave nothing") makes doctor report "not in a GitLab clone" even inside one.
- pytest 9 dropped Python 3.9, so the dev group needs pytest 8.4 to test on 3.9.

## Goals / non-goals / anti-goals

- Goal: `gl`, `/gitlab-client:setup` and `/gitlab-client:doctor` work on bare AL2023; the 3.9 floor is enforced by
  the same `make check` that CI runs.
- Goal: gitlab-client is presented as maintained.
- Non-goal: other plugins' Python floors; a Codex port of gitlab-client (it stays Claude-only — owner's call later).
- Non-goal: adding git to the requirements. `gl` keeps working without it.
- Anti-goal: a runtime dependency, a venv at runtime, or a change to the shared `Makefile`.

## Approaches

1. **Develop and test on 3.9 (picked).** A `.python-version` of `3.9` in `scripts/gitlab-client/` makes `uv sync`,
   `make check` and CI build the venv on 3.9; ruff and ty target 3.9; the dev group uses pytest 8.4. The launcher
   test then runs `scripts/gl` on 3.9 too (`uv run` puts the venv's `python3` first on `PATH`). No CI change.
2. Lint for 3.9, test on newer Python — cheaper, but misses runtime-only 3.10+ uses.
3. Approach 1 plus a CI step running the suite inside `amazonlinux:2023` — most faithful, but more CI plumbing for
   little over 1, which already tests on the same 3.9.25.

## Design

1. **Python floor 3.9** (`scripts/gitlab-client/`): `requires-python = ">=3.9"`, ruff `target-version = "py39"`, ty
   `python-version = "3.9"`, new `.python-version` (`3.9`), dev dep `pytest>=8.4` (whatever resolves on 3.9),
   `uv.lock` refreshed.
2. **Checklist check 1** → `python3` ≥ 3.9 (`sys.version_info >= (3, 9)`); remediation adds Amazon Linux / Fedora /
   RHEL (`sudo dnf install python3`). Mirrored in `commands/setup.md`, `commands/doctor.md` (list and sample output),
   `SKILL.md`, `README.md`, plugin `CLAUDE.md`.
3. **No git on the host:** when `gl` has no `--project`/`project:` and git isn't on `PATH`, it says so ("git isn't
   installed, so the remote can't be read — pass --project, or set project: …") instead of "gave nothing". Checklist
   check 7 maps that message to **WARN** with remediation (install git — `sudo dnf install git` — or pin `project:`).
   Setup step 5 says the same when `git remote get-url` can't run. README prerequisites: git optional, and without
   it the project settings file is read from the current directory (no repo root to find).
4. **Un-deprecate:** remove the notices in plugin `CLAUDE.md` and `README.md`, repo-root `CLAUDE.md`, `AGENTS.md`,
   root `README.md` (plugin table, layout comments, Codex paragraph), the `DEPRECATED — no longer maintained.` prefix
   of the description in `.claude-plugin/plugin.json` and `.claude-plugin/marketplace.json`, and the `deprecated`
   keyword. Wording that relied on "deprecated" to explain Claude-only becomes "Claude-only"; the portability test
   name follows.
5. **Version 0.1.3:** `.claude-plugin/plugin.json`, the `marketplace.json` entry, `pyproject.toml`, `uv.lock`,
   `__init__.py::__version__`.
6. **Keep it honest:** a plugin `CLAUDE.md` gotcha: the 3.9 floor is load-bearing (bare AL2023's `python3`), the dev
   venv is pinned to 3.9 by `.python-version` — don't raise it, and don't use 3.10+ syntax or stdlib.

## Verification

- `make check` in `scripts/gitlab-client/` on the 3.9 venv; repo gates (`scripts/check-version-sync.sh`,
  `python3 -m unittest discover -s scripts/tests`, `claude plugin validate` where the CLI is available).
- One-off, not committed: the suite and a `scripts/gl` smoke run inside `amazonlinux:2023` with no git installed,
  confirming the new message.
